# PEAK VPN 

Telegram-бот для автоматизированной продажи и выдачи доступа к VPN-сервису на протоколе VLESS + gRPC через панель Marzban, с приёмом платежей через ЮKassa.

## Архитектура

### Центральная панель управления (Marzban)

Является «мозгом» всей системы. На ней хранится единая база данных пользователей, учётные данные, лимиты трафика, настройки входящих подключений (Inbounds) и веб-интерфейс администратора.

Развёрнута на выделенном VPS с чистой Ubuntu. Установка выполняется через официальный скрипт, который автоматически поднимает окружение в Docker-контейнерах — саму панель, базу данных и веб-сервер.

К серверу привязано доменное имя. Панель администратора вынесена за Cloudflare Proxy с дополнительным слоем защиты (Cloudflare Zero Trust Access), домены VLESS-нод оставлены на DNS-only режиме — прямое соединение без прокси, обязательное условие для корректной работы Reality-хендшейка.

В панели настраивается связка **VLESS + gRPC**, которая упаковывает VPN-трафик в легитимные HTTP/2-потоки, делая его невидимым для систем глубокого анализа пакетов (DPI).

Панель предоставляет REST API с авторизацией по JWT-токенам (`/api/admin/token`), через которое Telegram-бот программно создаёт пользователей, продлевает подписки и получает готовые ссылки-подписки для выдачи клиентам.

### Telegram-бот (long polling, aiogram 3.x)

Бот — единственная точка взаимодействия клиента с сервисом: выбор тарифа, оплата, получение ключа, инструкция по подключению, поддержка. Работает через long polling — без вебхуков, без публичного порта, без белого IP на машине с ботом.

безлимитный трафик на всех тарифах. Цены и сроки хранятся централизованно в конфиге и подставляются автоматически во все тексты и клавиатуры бота.

**Пробный период:** выдаётся один раз на аккаунт, доступен только после подтверждённой подписки на Telegram-канал сервиса — бот проверяет членство через Bot API (`getChatMember`) перед активацией.

**Оплата (ЮKassa):** бот создаёт платёж и отдаёт клиенту ссылку на оплату; статус проверяется методом polling (клиент нажимает «Я оплатил», бот опрашивает API ЮKassa) — без необходимости в публичном webhook-эндпоинте. После подтверждённой оплаты бот обращается к Marzban API, создаёт или продлевает пользователя и присылает готовую ссылку-подписку.

**Один ключ на подписку:** каждому пользователю выдаётся персональный UUID в Marzban. Кнопка «Перевыпустить ключ» мгновенно генерирует новый UUID и инвалидирует старую ссылку — практичный механизм ограничения на одно активное устройство без сложной серверной логики отслеживания IP.

**Административные функции:** команда `/grant <tg_id> <дни>`, доступная только ID из списка администраторов, выдаёт доступ вручную напрямую из чата с ботом, без захода в панель Marzban — создаёт/продлевает ключ и уведомляет как администратора, так и получателя. При каждой оплате и выдаче пробного периода в личку администратору автоматически прилетает уведомление с деталями.

**Внутренний стек:** Aiogram 3.x — асинхронная обработка апдейтов и инлайн-клавиатур; SQLite (aiosqlite) — локальное хранилище связей Telegram ID ↔ юзернейм в Marzban ↔ статус платежей ↔ дата истечения; APScheduler — фоновый воркер, каждые 10 минут проверяющий истёкшие подписки и автоматически отключающий доступ в Marzban с уведомлением клиента.

### Удалённые ноды (Sing-box + Marzban-Node)

Логика разделения нагрузки: чтобы не держать весь трафик на одном сервере и иметь возможность гибко менять точку выхода при деградации конкретного узла, разворачиваются удалённые ноды в разных странах, подключённые к единой центральной панели.

На каждый удалённый VPS устанавливается высокопроизводительное ядро **Sing-box** вместе со специализированным агентом связи (`Marzban-Node`), который принимает конфигурацию от главной панели по защищённому каналу (клиентский сертификат), а не читает статичный файл с диска — это позволяет централизованно управлять всеми нодами из одного интерфейса, включая мгновенное обновление списка пользователей и параметров инбаунда без ручного захода на каждый сервер.

Когда клиент подключается по своей ссылке, устройство устанавливает соединение напрямую с удалённой нодой; нода через Sing-box проверяет валидность ключа, выпускает трафик в открытый интернет нужной страны и передаёт статистику потребления обратно на центральную панель.
